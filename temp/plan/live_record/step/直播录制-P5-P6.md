# P5 实现与 P6 验证记录

日期：2026-10-26；基线：main `9c409cf`。本次补齐 P5 采集、设置、导出和打包实现，推进 P6 故障隔离与发布检查。**工程实现完成不代表所有平台的实播验收已通过**；剩余门槛见文末。

## 已落地

| 平台 | 评论来源 | 本次验证范围 |
|---|---|---|
| Bilibili | 延续录播姬原生 XML；普通弹幕、礼物、SC | 原有 XML、隐私、导出回归通过；本次没有重复建立 B 站 WebSocket |
| YouTube | 独立 yt-dlp 子进程的原生 live_chat | 75 秒公开实播，70 条真实消息，解析拒绝 0；排除临时 `-FragN` 文件 |
| Withny | 原生 withny-dl 聊天 JSON | 验证原生尾逗号格式、逐频道配置覆盖、音频频道、同场文件匹配；尚无授权实播验收 |
| Twitch | 匿名只读 IRC WebSocket | 30 分钟、10,794 条消息；冻结版另收取 100 条真实消息 |
| TwitCasting | 网页 event.pubsub WebSocket | 45 秒公开实播、3 条消息，解析拒绝 0；状态探测改为 POST，当前场次由官方网页解析 |
| NicoChannel | messages.history HTTP 轮询 | 固定字段契约、token 刷新与重复事件测试；当前网络 TLS 连接失败，未实播验证 |
| Niconico | 观看页协商 + NDGR 正向流/历史 protobuf | 固定上游生成协议，测试拆包、历史补拉、重复段与权限失败；当前网络 TLS 连接失败，未实播验证 |

X 评论仍按计划不做。没有引入未经过 POC 的 Streamlink、biliup、twspace-dl 回退，也没有复制一套 Bilibili 协议。

设置增加 `LIVE_DANMAKU_PLATFORMS`：各平台可选择跟随全局、默认抓取、默认不抓取；全局默认关闭。单条、批量、等待开播后启动及 Withny 专用入口共用同一决策。Niconico 原来的点播评论开关只影响点播，避免直播出现第二条评论采集链路。

每次录制固定采集、格式、匿名化和偏移设置。`LIVE_DANMAKU_OFFSET_MS` 为 ±600000 毫秒，正数延后；已结束任务可以按当前格式和偏移重新导出。重新导出需要本版本的录制设置快照，沿用当次匿名化策略，校验任务 ID、路径和链接，拒绝活动任务及越界文件。

采集子进程与媒体进程隔离；队列上限 50,000，普通消息与礼物/SC 分开排队，溢出和重复均计数。网络失败退避，WebSocket 最短重连间隔 60 秒，限流至少等待 30 秒；鉴权、依赖缺失明确报告不可用。主程序退出会触发评论进程收尾，强制终止会保留事实日志并标记中断。JSONL 每 200 条或 1 秒同步，SQLite 可重建；匿名化键单独持久化，避免重建索引后昵称哈希变化。

Withny 使用任务私有 YAML，保留原配置及其相对凭据路径；覆盖逐频道 `writeChat` 和任务输出目录，禁止跨场自动拼接。文件按频道和原生场次 UUID 命名；原始 TS 与转封装文件都保留，报告优先选择转封装输出。字幕以录制文件时间估算，**不能把整场开播时间直接作为中途录制的起点**。

源时间、接收时间、节目内偏移分别保存。SRT/ASS 序列化继续交给 pysubs2；滚动、固定、SC 样式使用独立区域，密度超限丢弃并计数。没有可信媒体时钟时，报告保留未知误差；YouTube DVR 起点也不假设为节目零点。重新导出可以手动校正，但不等于自动完成精确同步。

## 一手依据与依赖

- [Twitch 官方 IRC](https://dev.twitch.tv/docs/chat/irc/)：TLS、标签、PING/PONG 和重连；匿名接入另以本次实播验证。完整机器人功能应参考其 [EventSub 迁移说明](https://dev.twitch.tv/docs/chat/irc-migration/)。
- [yt-dlp 原生 YouTube 聊天下载器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/downloader/youtube_live_chat.py)；[NicoChannel 提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/niconicochannelplus.py)。后者用于 token/history 字段契约，最新 120 条轮询仍需 NicoChannel 实播确认。
- [withny-dl 固定源码](https://github.com/Darkness4/withny-dl/tree/916fb9b1151ec76a78672a290aac8e7c040eecb7)：原生聊天、配置合并、输出模板与元数据格式。
- [NDGRClient 固定源码](https://github.com/tsukumijima/NDGRClient/tree/dab9bf7c915f41411d5986b521ce8fe937dde7f8)：观看协商、NDGR 分段和历史结构。仅下载其 12 个生成协议文件及 MIT 许可，不引入整个 SDK 及其编译扩展。
- TwitCasting 先参考[原作者协议研究](https://qiita.com/pasta04/items/d7b6132a15f13a9045f3)，再通过当前官方网站和真实 WebSocket 核验；没有把旧文章直接当成验收。
- [pysubs2](https://github.com/tkarabela/pysubs2)、[defusedxml](https://github.com/tiran/defusedxml)、[websocket-client](https://github.com/websocket-client/websocket-client) 分别负责字幕、XML 安全解析、WebSocket 传输。

运行库已安装到 `dependency/live-python/`。主依赖包括 pysubs2 1.8.0、defusedxml 0.7.1、websocket-client 1.9.2、protobuf 6.33.5、httpx 0.28.1、ruamel.yaml 0.19.1；共 17 个固定纯 Python wheel，13 个固定源码资产，URL、版本、许可及 SHA-256 见 `dependency/live-python.lock.json`。不修改系统 Python；升级命令为 `python scripts/install_live_dependencies.py --upgrade`，失败时保留旧运行库。

正式 spec 收集协议、TLS 证书、字幕/YAML 模块和全部 wheel 的许可元数据，保留 NDGR 许可；GPL 外部录制器仍不进入主 exe。依赖状态显示可选评论组件，发布前可运行 `python scripts/check_live_release.py`；源码和冻结版均支持 `--live-self-test`。

## 本次验收

- 最终全量：**501 passed / 49 subtests passed**。覆盖协议拆包、时间来源、配置覆盖、匿名化重建、队列背压、取消/父进程退出、故障报告、重导出鉴权与路径保护、依赖升级和既有录制流程。
- 直播目录语句覆盖率 **86.86%**；评论目录与 Withny 引擎合计 **92.71%**。这是语句覆盖率，不代表网络故障、平台权限及时间精度已经全部覆盖。
- Twitch 30 分钟评论采集，注入 90 秒连接中断；最终 10,794 条入库，重复、解析拒绝、队列丢弃均为 0。发生主动断线及额外连接中断，报告为 `partial`。没有宣称断线期间服务器评论无丢失。
- 真实 Twitch 媒体故障隔离：评论进程被强制终止后，媒体由 786,432 字节继续增长到 3,145,728 字节；最终视频约 91.93 秒，音视频轨及解码检查通过。358 条已保存评论完成字幕处理，评论报告保留中断和时钟估算；真实视频与 ASS 的 libass 渲染通过。
- 同一事件库重复导出、1080p ASS 分区/防碰撞、SRT 时间顺序和字符处理测试通过。实播检查修正了 IRC 多命令帧、YouTube 临时分片筛选及最终文件更名导致锚点后移的问题。
- 独立临时 WebUI 验证：逐平台开关、设置重载、偏移 1200 毫秒、重新导出按钮及成功提示；字幕首条从 1000 毫秒移至 2200 毫秒。窄屏控件挤压已修正，用户原配置未参与测试。
- 最终正式 spec 单文件构建通过，约 29 MB；冻结版字幕/协议/YAML/TLS 自检通过，源码发布检查通过。临时实播媒体、原始评论、协议研究副本、下载缓存、验收脚本及构建工具/产物在提交前清理；保留运行依赖、必要回归测试和发布检查脚本。

## 仍需发布前确认

1. NicoChannel、Niconico 在可连通且具备观看权限的环境进行实播；Withny 使用授权频道完整验收。当前不把协议样本测试算成这些平台的成功实播。
2. 原计划“30 分钟首条字幕误差 <2 秒”尚未通过。当前使用明确披露的时钟估算，尚需可靠媒体时钟/PDT 或人工测量校准；不能承诺所有平台自动精确同步。
3. 逐平台 WAIT 提前/延迟、广告、删档、长场、重启与完整断网矩阵，以及 P4 同码流无缝追播，继续作为 P6 发布门槛。未声称整个 P6 完成。
