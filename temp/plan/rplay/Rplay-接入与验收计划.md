# Rplay 接入与验收计划

日期：2026-10-28。对象：[rplay.live](https://rplay.live/)。本次交付是设计计划，尚未增加 Rplay 下载或录制能力。

## 1. 调研结论与证据边界

| 来源 | 已观察到的实践 | 使用方式 |
| --- | --- | --- |

这是开源实现和公开页面的研究，尚未用本项目完成 Rplay 真实录制。点播详情接口、点播 URL 全部变体、评论协议、DVR、广告时间轴均需 R0 取样确认。官方网页未提供本轮可核验的完整稳定 API 合同。

## 2. 首版范围与不做的内容

首版支持用户已有观看权限的普通点播、直播当前时刻录制、持久化蹲开播，并沿用任务列表、停止收尾、完整性报告和代理设置。评论采集在协议与真实样本通过后开放。

首版遇到 DRM 返回明确的不支持原因；不实现 CDM、DRM 解密、购买、代付、越权观看、自动发送评论。直播追开播初始声明为不支持，待证明存在可用 DVR 和同场历史片段后再单独开放。全站归档、大量频道扫描和复杂通知不是首版目标。

## 3. 复用现有架构

```text
UI / HTTP / TaskManager
    → URL 分类 / RplayResolver / RplayProbe
    → RplayClient ← AuthProvider / 既有代理与超时策略
    → 点播：现有下载执行器 + 独立提取器
    → 直播：LiveRunner + RplayEngine + 会话/完整性报告
    → 评论：独立 CommentSource → 事件库 → pysubs2 SRT/ASS
```

- `core/platform.py`、`constants.py`、`paths.py`：注册 Rplay 和 `download/Rplay`，统一命名、历史与平台筛选；单独增加平台卡片不代表已经实现。
- `live/urls.py`：区分创作者主页、直播、点播与列表。已有参考 URL 为 `/creatorhome/{creatorOid}` 和 `/live/{creatorOid}`；点播路径以 R0 的当前真实页面为准。
- 新增 `platforms/rplay/{models,client,auth,resolver}.py`：协议细节集中于客户端；业务返回值不暴露令牌或带签名播放地址。
- `live/probe.py` 注册 Rplay provider；复用 UNKNOWN/OFFLINE/UPCOMING/LIVE/ENDED/PRIVATE/ERROR，不把鉴权失败当作未开播。
- `live/engines/rplay.py`：实现现有引擎契约，不另建一套重试、磁盘预检、超时和会话状态机。
- `live/danmaku/rplay.py`：只处理评论传输、去重与源时间；复用存储、匿名化、时间投影和导出器。
- 提取器优先采用项目自己的 yt-dlp 插件。只有插件接口确实不满足时才增加 Rplay 专用 worker，禁止替换全局 yt-dlp 为长期分叉版本。

这些模块路径为拟议新增位置；开发时遵守已有入口契约，避免让 UI 直接调用平台 API。

## 4. 认证与请求可靠性

参考实现的关键调用为 `GET /live/livestreams`、`POST /rplay/account/refresh-token`、`GET /live/key2` 和 `/live/stream/playlist.m3u8`。这些是调研到的接口，不是官方稳定性承诺。[客户端依据](https://github.com/Zhen-Bo/rplay-live-dl/blob/main/core/rplay.py)

1. 先确认当前浏览器如何保存登录态、令牌过期及轮换规则。不能只实现 cookies.txt 就宣称登录可用，也不能假设每个浏览器均把令牌放在同一存储位置。
2. 默认只在当前进程保存访问令牌；UI 展示“未配置 / 可用 / 即将过期 / 需重新登录”，不展示原始值。可选记住登录状态时，Windows 使用 DPAPI 保护，配置文件仅保存引用。
3. 刷新操作按账号串行，同一过期时刻只刷新一次；401 最多刷新一次再重试，403 区分无权限并停止重试。刷新轮换未确认前，不擅自消耗浏览器中的一次性刷新凭据。
4. 429 尊重 Retry-After，5xx/网络错误有界退避。开播瞬间 404 可短时重试；真正删档不能无限轮询。
5. 探测、媒体、评论使用同一代理与授权上下文。重定向时不向任意外域转发认证头；签名 CDN 地址按实际允许域和请求需求处理。
6. 令牌、key2、完整签名 URL 不写历史、session/report、日志、SSE、剪贴板命令或测试快照。若必须经子进程使用，优先受保护临时上下文/本地代理；退出后清理。

## 5. 视频下载

- 解析点播 ID、标题、作者、封面、时长、权限、媒体类型及清晰度。优先解析授权播放响应，避免把页面上任意 m3u8 当成目标视频。
- HLS 与 DASH 分开列出能力；配对真实音视频轨，沿用画质上限、音频方案、输出容器和 FFmpeg 后处理。不能固定假设 H.264/AAC 或单轨文件。
- 片段地址过期时重新解析同一个点播资源；确认 ID/格式一致后才续传。不能把新的资源追加到旧 `.part`。
- 文件命名与输出目录复用 `AppPaths`；覆盖含空格/中文路径、已存在文件、下载归档去重、单条和混合批量任务。
- 字幕与封面工具按能力接入：有真实字幕轨才提供字幕；不存在时显示“未提供字幕”。不把直播评论当作点播字幕。
- 点播列表分页、合集和创作者全量下载列为后续扩展；首版可先支持单个点播 URL。

## 6. 直播录制与 WAIT

- 原生直播走 `LiveRunner`：启动预检、用户停止、超时、磁盘不足、无增长、崩溃、断线重试都写会话和完整性报告。
- 直播身份首选经验证可区分场次的服务端 ID；同时记录 creatorOid 与开播 UTC。不能只用 creatorOid 去重，否则下一场会漏录；也不能每次探测都创建新场次。
- 重连前重新获取播放地址与权限，分段落盘。只有同场、同编码且证据足够才拼接；无法证实时保留分段并报告缺口。
- WAIT 复用 SQLite、取消与原子认领机制；提前开播、推迟开播、开播时登录过期、重启和重复探测均需测试。未确认的服务端预定时间不强行伪造。
- YouTube/Twitch 转播先向用户说明来源；如果转交既有平台，重新检查源平台权限和参数，禁止把 Rplay 认证转发过去。
- 广告、静音和播放列表 discontinuity 不直接等于断流。媒体正常但评论不可用时继续录制，两个结果分别报告。

## 7. 评论与时间轴

R0 先确认当前网页使用 WebSocket、Socket.IO、SSE 还是其他协议，以及鉴权、心跳、历史分页、限流、断线补发与事件 ID。现有资料不能证明评论已可采集，因此暂不指定新的传输依赖。

- 有平台原生评论文件时优先复用，避免重复连接；无原生文件再实现独立 source。
- 最低事件字段：平台、场次、源事件 ID、源时间及单位、接收 UTC、类型、正文、昵称和 UID；普通评论与礼物分别归类。
- 断线补取按源事件 ID 去重；没有历史接口时明确报告丢失区间。不能用轮询收到的时间冒充发言时间。
- 同步优先使用服务端媒体时钟/PDT 等可验证锚点；广告、重连、时间重置分段映射。无锚点只标估计，允许人工微调与重新导出。
- “小于 2 秒”验收需要整场多个独立锚点，并报告测量误差、未映射数量、断线前后及广告区间；只取一个开头样本不能通过整场验收。

## 8. UI、设置与可访问性

| 界面 | 具体改动与验收 |
| --- | --- |
| 平台选择/URL 输入 | 新增 Rplay，自动识别实际 URL；不支持的路径显示原因；长链接和中文目录正常 |
| 任务前检查 | 展示直播/点播/离线/需登录/无权限；只提供当前实现的录制模式 |
| 任务与历史 | 显示真实场次、录制引擎、分段/缺口、评论状态与报告入口；用户停止不显示成“完整录制” |
| 登录设置 | 选择身份来源、检测状态、重新登录提示、清除本地凭据；不在普通文本中回显秘密 |
| 评论设置 | source 实测通过后新增 Rplay 的“跟随全局 / 默认抓取 / 默认不抓取”；未实现时禁用并说明 |
| 画质/音频/代理 | 复用既有设置；不支持的组合提前提示，不能静默忽略 |
| 小工具 | 点播封面/字幕按解析能力复用；不支持的入口给具体错误 |
| 键盘/小屏 | 表单有标签、状态可被读屏读取、按钮禁用/恢复正确，窄屏无横向溢出 |

拟新增普通配置仅 `RPLAY_AUTH_PROFILE`（引用，不含密钥）、`RPLAY_REMEMBER_AUTH=0`。平台默认录制/评论沿用 `LIVE_PLATFORM_MODES`、`LIVE_DANMAKU_PLATFORMS`，避免再加一套重复开关。令牌刷新提前量、接口地址和底层重试策略先保留为实现常量，避免给普通用户增加无用参数。

## 9. 分阶段交付与退出条件

| 阶段 | 交付 | 必须通过后才能进入下一步 |
| --- | --- | --- |
| R0 调查 | 当前 URL、权限、媒体类型、认证和评论协议的脱敏样本；依赖/许可选择 | 至少一个点播、一个直播；区分已验证与待验证，样本不得含令牌 |
| R1 只读接入 | 平台注册、URL 分类、客户端、认证检测、Probe | 正常/过期/无权限/离线可区分；日志无凭据；不误触发下载 |
| R2 点播 MVP | 单 URL、画质/音频、代理、历史、封面、错误提示 | 真实 HLS 点播完整解码；有 DASH 样本再开放 DASH；错误文件与半成品不冒充成功 |
| R3 直播 | LIVE_EDGE、WAIT、会话、停止、重连 | 至少一次 30 分钟真实录制，用户停止后音视频有效；WAIT 真实开播一次；受控断网后明确报告缺口 |
| R4 评论与 UI | 事件 source、逐平台开关、SRT/ASS、重导出 | 同时有真实媒体和评论；重连去重；未知同步误差不能标已验证 |
| R5 发布 | 源码/冻结程序一致、依赖锁与许可、清理 | 全量回归通过；Windows 中文空格目录与独立便携目录验证；所有测试产物清理 |

建议每一阶段完成一个中文功能提交。R2/R3 可先形成有明确限制的可用版本，R4 不应阻塞普通点播交付。R0 若发现主要目标内容仅提供 DRM，先停止对应媒体下载范围，保留只读状态和可支持的普通媒体接入。

## 10. 测试矩阵与依赖决定

- 合同测试：URL 正反例、身份/场次去重、过期刷新并发、401/403/404/429/5xx、响应缺字段、签名过期、跨域认证隔离、取消竞态和重启。
- 真实数据：点播完整下载及音画轨检查；直播 30 分钟和一次 2 小时长场；60–90 秒断网与恢复；评论独断、媒体独断；账号失效；WAIT 提前/延迟。广告、删档与会员场景需相应真实样本，没有样本就记“未验收”。
- 质量门槛：新增协议模块行覆盖率目标不低于 90%，直播总体不得低于现有 85% 门槛；覆盖率与真实平台验收分别记录，不互相替代。
- 同步验收：记录锚点来源及不确定度，多个分散样本和断线边界均满足预算后，才对该场次声明小于 2 秒；不能升级成全平台保证。
- 优先复用现有 yt-dlp、FFmpeg/ffprobe、httpx、现有 WebSocket 传输和 pysubs2。协议确有需要才下载新依赖到 `dependency`，固定版本、来源、SHA256 和许可证，并验证冻结打包。
- 不在计划阶段下载整套 Docker 工程、替换全局 yt-dlp、安装浏览器扩展或引入用途未确认的评论依赖。本次没有新增 Rplay 运行时依赖。
