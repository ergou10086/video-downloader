# 任务并发与网络自动调整

更新日期：2026-10-24。

## 默认设置

| 设置 | 默认值 | 范围/行为 |
| --- | --- | --- |
| 最大并行任务数 | 2 | 1～5，1 为任务间串行 |
| 任务内直播与下载并行 | 开启 | 关闭后按输入顺序逐条执行，直播与视频均不重叠 |
| 任务内直播并行数 | 2 | 2～5 路，仅在任务内并行开启时生效 |
| 任务内视频并行数 | 1 | 1～5 路，默认视频串行 |
| 普通下载限速 | 0 | 每条任务内普通 yt-dlp 视频的 MiB/s 上限，0 不限；不限制直播 |
| 任务排序 | 不排序 | 保留原 FIFO / 直播优先 / 下载优先规则 |

一次“开始”点击仍然对应一个父任务。开启任务内并行后，直播与视频使用两份独立额度：即使视频排在输入列表前面，两路直播也会同时启动；直播排在前面也不会占住视频额度。同类链接按照输入顺序获取各自槽位。

默认两个父任务共最多运行 4 路直播和 2 路视频；手动设到全部上限时共最多运行 25 路直播和 25 路视频。每条 yt-dlp 链接还会使用其分片线程数，这些上限不代表网络或磁盘一定能承受。

父任务并发上限与排序对队列实时生效；调低上限不会中断已运行任务，只限制后续启动。任务内并发与限速在提交时固定。普通队列依然不跨程序重启恢复。

## 旧设置和预设迁移

有效的旧配置保留，不会强行覆盖用户已经选择的父任务数。原先超出新上限的 6～8 个父任务会收敛到 5；旧的任务内直播数量 1 调整为 2，6～8 调整为 5；缺失的新字段使用表中的默认值。恢复默认设置后会使用新的 2 / 开启 / 2 / 1 配置。

## 如何自动调整

1. 完成或取消当前运行及排队任务。
2. 在“设置 → 网络与代理”配置要使用的直连、HTTP 或 SOCKS5 代理。
3. 点击“快速检测网络”。程序保存当前设置后检测，期间阻止启动新下载和维护操作。
4. 检测结束后查看测量结果与两套参数预览。
5. 点击“应用高性能”或“应用高可靠”，配置校验并保存成功后用于新任务。

检测可取消，刷新页面可恢复检测进度和当前进程内的结果。结果有效期为 15 分钟，代理设置变化后拒绝套用旧结果；切换 Wi-Fi、VPN、运营商线路等物理网络后，也应手动重新检测。

检测和应用方案都与下载、录制、更新、临时文件清理互斥；取消或失败后会释放维护状态。保存方案失败时恢复之前的全部配置，其他画质、Cookie、输出格式及排序设置不被推荐方案覆盖。

## 测量范围与限制

检测使用 [Cloudflare 公共测速下载接口](https://github.com/cloudflare/speedtest)，通过系统 curl 发起请求，支持与应用一致的 HTTP/SOCKS5 配置。未找到 curl 时只禁用检测，不影响下载功能。不会携带视频 Cookie、访问用户视频链接、上传文件，或读取用户浏览器凭证；关闭代理时显式忽略系统代理环境变量。

本轮测试有约 20 秒时间预算、最多 32 MiB 响应正文数据（不含协议开销），包含：

- 3 次空载 HTTP 探针；
- 小数据预热及自适应的 2 次单连接吞吐请求；
- 最多 3 路同时传输和重叠的 HTTP 延迟探针。

HTTP 延迟取首字节时间，包含 DNS、TCP、TLS 等开销，并不是 ICMP ping。抖动来自 HTTP 首字节时间的相邻差值；请求失败率也不等于 UDP 丢包率。负载延迟要求至少一条正文传输持续 250 毫秒，并与探针实际重叠；只有握手重叠或下载过短时显示“未测得”。所有正文传输都太短时也会收敛高性能推荐。

带宽高低位是本轮有效观测值，不能证明线路的绝对上限、长期下限或各个平台 CDN 的可用带宽。检测不测上传能力、磁盘写入、CPU 转码、长期断流和具体直播码率。测试节点不可达或有效样本不足时不给出配置；部分失败或短样本会降低推荐的并发额度。

## 两套方案如何选择

**高性能**使用本轮吞吐高位估计可用容量，提高父任务数、每任务直播/视频额度，结合总体连接预算分配分片线程。观察到 HTTP 请求失败、明显抖动或负载延迟增长时收敛并发；样本有限时也不会直接采用最大值。

**高可靠**使用本轮吞吐低位预留余量：正常样本使用约 65% 的低位作为规划预算，线路不稳定时使用约 45%。父任务最多推荐 2 个，每任务视频保持 1 路，再把保守预算的一部分分配为每条视频的限速，为直播保留空间。它是一套启发式参数建议，不是录制完整性的保证。

两套方案都保持任务内双通道开启，直播额度至少为 2，且不修改任务排序。应用时会把旧的全局限速清零，以免对直播限速；高可靠改用仅针对任务内普通 yt-dlp 视频的限速。预览明确列出这些修改。

直播码率因平台、画质和编码而不同；过低带宽即使减少分片线程也无法支撑多路录制。界面会在观测低位较低时提示减少任务或降低画质。Withny 专用 HAR/监控流程不使用 yt-dlp 视频限速。关闭任务模式后不使用任务级通道或该视频预算。

## 验证记录

- 最终全量回归：356 项通过、22 项因缺少 Python yt-dlp 包而跳过，另有 24 个子测试通过；JavaScript 语法检查通过。
- 回归覆盖直播/视频两种输入顺序、独立额度、关闭并行、两类各 5 路、父任务最多 5 个、取消与视频限速不影响直播。
- 覆盖旧配置/预设迁移、HTTP 路由鉴权和字段类型、网络取消、失败时不生成虚构配置、保存回滚、结果过期、代理变化和维护互斥。
- 本机真实直连烟雾测试约 3.2 秒完成，接收约 6.92 MiB 数据；本轮观测约 18.55～39.49 Mbps。该数值只代表该次测试，不代表稳定承诺或用户视频平台的速度。
- 浏览器界面使用模拟网络样本验证检测进度、两套方案预览/应用、刷新回填，以及默认两路直播加一路视频同时运行；未修改用户实际配置或进行真实直播录制。
