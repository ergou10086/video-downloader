# 直播录制 P4 与部分 P5（2026-10-25）

本轮实现 YouTube/Twitch 条件追播，以及 Bilibili 录播姬 XML → 事件库 → SRT/ASS。原计划中的自研 B 站 WebSocket 和手写字幕序列化改为复用现有组件。YouTube/Withny 评论采集、其他平台评论和独立实时消费留待 P5 后续实施。

## 行为与设置

- YouTube：探测到 yt-dlp 返回 `is_from_start` 的直播 DASH 后，才使用单进程追播。无法验证时自动从当前录制，说明原因；运行中追播失败仍尝试实时尾部。平台 DVR 窗口无法精确确认时保持未知，不承诺从最初开播点开始。
- Twitch：验证频道、开播时间和本场 VOD 身份，拒绝误用上一场录像。实时主进程先启动，回填使用独立子进程和目录。回填失败、无法启动或取消均不得终止实时媒体。执行端元数据探测可取消并有超时上限，不会让停止操作等待整个探测超时。音频特殊处理和回填磁盘预算不满足时，明确降级为当前录制。
- 拼接：核对实际音视频轨、时间基和 codec extradata；封面附加视频轨不参与录制内容匹配。至少连续 8 个视频包和 8 个音频包的 SHA-256 与时间偏移一致，才确定重叠边界。FFmpeg concat 关闭自动比特流转换，按 DTS 去掉回填重叠；输出还需通过完整性检查和各轨包序列指纹比对。任一检查失败均不发布合并文件，保留两路原件并报告 `gaps`。不按墙钟猜测裁剪点，不重编码掩盖差异。
- 弹幕：`LIVE_DANMAKU_ENABLED=0` 默认关闭；`LIVE_DANMAKU_FORMATS=srt,ass`，可选单一格式；`LIVE_DANMAKU_ANONYMIZE=0`。关闭时录播姬使用 `--danmaku None`，打开时使用原生 XML，不再额外连 WebSocket。
- 用户设置在任务提交时固定。界面、配置校验、INI/预设、任务执行和录制报告均已接线；新增开关支持键盘与读屏状态。

## 字幕与时间轴

解析录播姬原生普通弹幕、SuperChat、礼物及舰长购买。`defusedxml` 禁止 DTD/实体扩展，仅读取 XML 根元素的直接子节点，不执行文件内 XSLT。截断文件可保留已闭合的消息，同时明确报告截断；无效消息计入拒绝数量。

`p[0]` / `ts` 是每个 XML 对应媒体段的相对时间，`p[4]` 是发送时间，`p[7]` 固定为 0，不能当作消息 ID。事件保留来源相对时间、平台绝对时间和导出定位的区别，不把文件创建时间伪造为精确媒体锚点。

每个媒体段生成同名 `.srt` / `.ass`。不同原件之间未验证的拼接不共享一份字幕时间轴。当前 `anchor_error_ms=null`，表示尚未实测标定，不等于 0 毫秒误差。负偏移与超出媒体范围的事件保留在事件库，导出时丢弃并计数。

JSONL 是事实记录，SQLite WAL 是可重建索引。每 200 条或 1 秒同步，关闭时同步并 checkpoint；重开时恢复完整 JSONL 行、截去最后一条未完成行、重建索引并去重。每次导出按源时间及稳定主键排序。匿名化采用会话盐值 HMAC；原始 XML 不作改写，仍包含 UID/昵称，不能将“派生导出匿名化”理解为原件已经匿名。

SRT/ASS 的格式、样式和时间序列化交给 `pysubs2`。适配层处理不可信用户文本、CJK 折行和负偏移；SRT 不通过整体延时积累错误，拥挤时丢弃并计数。ASS 分开滚动、顶部和底部区域，轨道等前一条完全离开才复用；使用 ffprobe 的实际分辨率。此策略优先避免重叠，不追求最高弹幕密度。

评论失败单独记录在 `comments-report.json` 与媒体报告的 `comments` 字段，不更改媒体的成功/失败结论。任务生命周期日志仍是根目录 `events.jsonl`；评论事件位于 `danmaku/events.jsonl`，避免两种日志混用。

## 依赖和构建

```powershell
python scripts/install_live_dependencies.py
```

安装到 `dependency/live-python/`，不修改系统 Python。锁定 `pysubs2==1.8.0`（MIT、Python ≥3.9）和 `defusedxml==0.7.1`（PSFL），均无额外运行时依赖。`dependency/live-python.lock.json` 记录官方 wheel URL 与 SHA-256；安装器先校验哈希与解压路径，再原子发布目录。离线 pip 安装也可使用 `requirements-live.txt` 的哈希锁定条目。

正式 spec 收集 `pysubs2`、`defusedxml.ElementTree`，并将 NOTICE 和许可文本放入 EXE 的 `licenses/`。录播姬继续外置。`websocket-client`、NDGRClient/protobuf、twspace-dl、chat-downloader-fork 以及额外弹幕转换引擎本轮均未引入：当前实际支持的采集来源不需要它们，后续平台接入时再做版本、许可和真实源 POC。

- [yt-dlp 官方直播选项](https://github.com/yt-dlp/yt-dlp#usage-and-options)：追播为实验性能力，不能按平台名字直接认定每场都支持。

- [固定版本 YouTube 提取器](https://github.com/yt-dlp/yt-dlp/blob/2026.08.19/yt_dlp/extractor/youtube/_video.py)：`is_from_start`、直播 DASH 与动态分片行为。
- [录播姬弹幕文档](https://rec.danmuji.org/user/danmaku/)及[固定版本 XML 写入器](https://github.com/BililiveRecorder/BililiveRecorder/blob/v2.20.0/BililiveRecorder.Core/Danmaku/BasicDanmakuWriter.cs)：支持的事件类型、相对时间和实际字段；此项目未复制其 GPL 实现。
- [pysubs2 官方 API](https://pysubs2.readthedocs.io/en/latest/api-reference.html)和[1.8.0 发布元数据](https://pypi.org/pypi/pysubs2/1.8.0/json)：格式 API、运行条件与 wheel 校验信息。
- [defusedxml 官方项目](https://github.com/tiran/defusedxml)：XML 实体与 DTD 防护。
- [FFmpeg concat demuxer](https://ffmpeg.org/ffmpeg-formats.html#concat)、[FFprobe](https://ffmpeg.org/ffprobe.html)：DTS 边界、相同轨道要求与包哈希检查；本轮同时以本机真实二进制验证。
- [SQLite WAL 官方文档](https://www.sqlite.org/wal.html)：事务索引与 checkpoint。
